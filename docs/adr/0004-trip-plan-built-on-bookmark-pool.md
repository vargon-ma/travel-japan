# ใช้ Bookmark เป็น pool เดียวสำหรับ Trip Plan ไม่แยกระบบ "เพิ่มเข้าทริป"

Trip Plan (แผนเที่ยว) ต้องมีที่มาของ Entry ที่จะจัดลงวัน เราเลือกให้ Entry ต้องถูกบุ๊กมาร์กก่อนเสมอถึงจะจัดลง Trip Day ได้ แทนที่จะสร้างกลไก "เพิ่มเข้าทริป" แยกต่างหากที่ทำงานอิสระจากบุ๊กมาร์ก เพราะทำให้มี pool เดียว (Bookmark) ที่เป็นความจริงเสมอ ลด UI/state ซ้ำซ้อน และ mental model ของผู้ใช้ง่ายกว่า ("ถูกใจ" → "จัดวัน")

## Considered Options

- **ระบบ "เพิ่มเข้าทริป" แยกต่างหาก** (ไม่ผูกกับบุ๊กมาร์ก) — ปฏิเสธ เพราะจะมี pool ของ "สิ่งที่ผู้ใช้สนใจ" สองชุดที่อาจไม่ตรงกัน (บุ๊กมาร์กไว้แต่ไม่ได้อยู่ในทริป, อยู่ในทริปแต่ไม่ได้บุ๊กมาร์ก) เพิ่มความสับสนและโค้ด state ซ้ำ

## Consequences

- เลิกบุ๊กมาร์ก Entry ที่จัดอยู่ใน Trip Day แล้ว = เอาออกจาก Trip Day นั้นทันทีโดยอัตโนมัติ (ไม่มีทางที่ Entry จะอยู่ใน Trip Day โดยไม่ได้บุ๊กมาร์ก)
- ปุ่ม/dropdown สำหรับจัดลงวัน อยู่เฉพาะในมุมมอง "แผนเที่ยว" เท่านั้น — การ์ดกริดไม่ต้องเพิ่ม UI ใหม่
- ถ้าในอนาคตอยากให้ Trip Day มี Entry ที่ไม่ได้บุ๊กมาร์กไว้ด้วย (เช่น เผื่อสถานที่ที่ยังไม่ตัดสินใจ) ต้องรื้อ invariant นี้ใหม่
